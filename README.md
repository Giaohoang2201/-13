3. 실험 방법
데이터: rand() % 100000 으로 만든 무작위 정수 (중복 허용, srand(12345) 로 시드를 고정하여 재현 가능).
데이터 크기: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000.
각 크기마다 원본 배열 1개를 만들고, 알고리즘마다 memcpy로 복사한 배열을 정렬한다. 따라서 4개 알고리즘은 모두 동일한 데이터를 사용한다.
정렬 후 is_sorted() 로 오름차순 여부를 검사하며, 모든 경우 OK 였다.
비교 횟수: 데이터 값끼리 비교하는 지점(병합 시 a[i] <= a[j], 퀵 정렬의 분할 비교 a[j] < pivot, 중앙값 선택의 3회 비교)마다 전역 카운터를 증가시킨다. 반복문의 인덱스 및 종료 조건 검사는 세지 않는다.
실행시간: clock_gettime(CLOCK_MONOTONIC) 으로 정렬 호출 직전과 직후의 차이를 ms 단위로 측정한다. 데이터 생성, 배열 복사, 출력 시간은 제외한다. (병합 정렬의 임시 배열 malloc은 정렬에 필요한 비용이므로 측정에 포함된다.)
4. 메모리 사용량 측정 방법과 계산 기준

프로파일링 도구를 쓰지 않고 직접 계산하였다. 64비트 환경을 가정한다.

최대 추가 메모리 = 보조 배열 크기 + (최대 재귀 깊이 × 호출 1회당 스택 프레임 크기)
최대 재귀 깊이: 재귀 함수 진입 시 깊이를 1 증가, 종료 시 1 감소시키며 실행 중 최댓값을 기록한다 (실측값).
스택 프레임 크기: 매개변수 + 지역변수 + 복귀 주소(8B) + 저장된 rbp(8B)를 16바이트로 정렬한 값.
merge_sort_rec(int*, int*, int, int) : 8+8+4+4 + 지역변수 mid(4) + 16 = 44 → 48 Byte
quick_sort_rec(int*, int, int, int) : 8+4+4+4 + 지역변수 p(4) + 16 = 40 → 48 Byte
병합 정렬: 크기 n의 임시 배열 n × sizeof(int) = 4n Byte + 재귀 스택.
퀵 정렬: 제자리(in-place) 정렬이므로 보조 배열이 없고, 재귀 스택만 계산한다.
원본 데이터 배열은 공통 비용이므로 제외하였다. 컴파일러 최적화에 따라 실제 프레임 크기는 달라질 수 있으므로 이 값은 추정치이다.

6. 비교 및 분석
6.1 데이터 크기 증가에 따른 비교 횟수 변화

n이 2배가 될 때 병합 정렬의 비교 횟수는 8,720 → 19,416 → 42,825 → 93,558 → 203,338 으로 대략 2.2배씩 증가하였다. 이는 O(n log n)의 전형적인 증가 양상이다(n이 2배가 되면 2배보다 약간 큰 비율). 퀵 정렬도 같은 경향을 보인다.

n = 20,000에서 n·log₂n ≈ 285,754 이다. 병합 정렬은 260,725회로 이 값의 약 0.91배, 퀵 정렬(First)은 318,922회로 약 1.12배이다. 모든 크기에서 병합 정렬의 비교 횟수가 퀵 정렬보다 적었다 (n=20,000에서 퀵(First) 대비 약 18% 적음). 그 이유는 동작 방식 차이에 있다.

병합 정렬은 항상 배열을 정확히 절반으로 나누므로 재귀 트리 높이가 ⌈log₂n⌉로 일정하고, 병합 시 비교 횟수가 최대 (길이 − 1)회이며 한쪽이 먼저 소진되면 나머지는 비교 없이 복사한다.
퀵 정렬은 분할마다 피벗과 나머지 모든 원소를 비교하며, 피벗이 정확히 중앙에 오는 경우가 드물어 분할이 불균형해지므로 평균 비교 횟수가 약 1.39·n·log₂n 으로 병합 정렬(약 n·log₂n)보다 많다.
6.2 실행시간 차이

비교 횟수는 병합 정렬이 적었지만 실행시간은 모든 크기에서 퀵 정렬(First)이 가장 빨랐다 (n=20,000: 병합 1.3634ms, 퀵(First) 0.9441ms로 병합이 약 1.4배 느림). 이는 시간이 비교 횟수만으로 정해지지 않음을 보여준다.

병합 정렬은 병합할 때마다 값을 임시 배열에 복사하고, 다시 원래 배열로 되돌려 쓰므로 데이터 이동(쓰기)이 약 n·log n 회이다. 또한 임시 배열 malloc/free 비용도 포함된다.
퀵 정렬은 제자리에서 교환(swap)만 하며, 분할 시 배열을 순차적으로 훑기 때문에 캐시 지역성이 좋고 추가 복사가 거의 없다.
즉, 병합 정렬은 "비교는 적지만 메모리 이동이 많고", 퀵 정렬은 "비교는 더 많지만 한 번의 비교·이동 비용이 작다"고 해석할 수 있다.
6.3 메모리 사용량 차이

메모리 차이가 가장 극명하였다. n = 20,000에서 병합 정렬은 80,768 Byte, 퀵 정렬은 1,200 ~ 1,632 Byte로 병합 정렬이 약 50~67배 많았다.

병합 정렬의 추가 메모리는 임시 배열 4n Byte(80,000 Byte)가 대부분이고 재귀 스택은 768 Byte(깊이 16 × 48)에 불과하다. n이 2배가 되면 메모리도 거의 정확히 2배(4,528 → 8,576 → 16,624 → 32,672 → 64,720 → 80,768)가 되어 O(n) 임을 확인할 수 있다.
퀵 정렬은 임시 배열이 없고 재귀 스택만 사용한다. n이 20배로 커져도 메모리는 960 → 1,200 ~ 1,632 Byte로 소폭만 증가하였다(재귀 깊이가 20~34 수준). 이는 평균적으로 O(log n) 에 가까운 증가이다.
6.4 퀵 정렬의 피벗 선택 방법에 따른 성능 차이
이번 실험의 데이터는 완전히 무작위이므로 세 방법 모두 평균적인 O(n log n) 성능을 보였고, 비교 횟수 차이는 크지 않았다 (n=20,000: First 318,922 / Random 332,727 / Median3 317,121).
Median-of-Three는 대부분의 크기에서 First와 비슷하거나 약간 적은 비교 횟수를 보였고(n=4,000, 16,000, 20,000), 재귀 깊이가 가장 작아 메모리가 가장 적었다(n=20,000: 1,200 Byte). 중앙값 선택으로 분할이 더 균형 잡혀 재귀 트리가 얕아지기 때문이다. 다만 분할마다 비교 3회가 추가되므로 작은 n에서는 오히려 비교 횟수가 많을 수도 있다(n=1,000: 11,424회로 가장 많음).
Random은 비교 횟수가 일정하지 않았다(n=16,000, 20,000에서는 가장 많음). 피벗이 우연히 불균형하게 선택되면 깊이가 커져 메모리(1,632 Byte)도 가장 많이 사용하였다. 난수 생성 비용으로 시간도 First보다 조금 더 걸렸다. 하지만 Random의 장점은 입력이 이미 정렬되어 있거나 역순인 경우에도 최악의 경우(O(n²))를 확률적으로 피한다는 것인데, 이번 무작위 데이터에서는 이 장점이 드러나지 않았다.
First는 구현이 단순하고 추가 비용이 없어 무작위 데이터에서 가장 빨랐지만, 정렬된 입력에서는 O(n²)으로 악화되는 약점이 있다(이번 실험에서는 확인하지 않음).
6.5 시간 복잡도 및 공간 복잡도 비교
구분	병합 정렬	퀵 정렬
최선 시간	O(n log n)	O(n log n)
평균 시간	O(n log n)	O(n log n)
최악 시간	O(n log n)	O(n²) (피벗이 항상 최솟값/최댓값일 때)
공간 복잡도	O(n) (임시 배열) + O(log n) 스택	O(log n) 평균 (최악 O(n) 스택)
안정 정렬	예	아니오

병합 정렬은 입력 분포와 관계없이 항상 O(n log n)을 보장하지만 O(n)의 추가 공간이 필요하다. 퀵 정렬은 제자리 정렬이라 추가 공간이 거의 없고 실제로 더 빠르지만, 피벗 선택이 나쁘면 최악의 경우 O(n²)이 될 수 있어 Random 또는 Median-of-Three로 이를 완화한다.

6.6 결론
기준	우세한 알고리즘	이유
비교 횟수	병합 정렬	항상 균등 분할, 한쪽 소진 시 비교 생략
실행시간	퀵 정렬	제자리 교환, 복사 적음, 캐시 효율
메모리	퀵 정렬	임시 배열이 없음 (병합은 O(n))
최악 성능 보장	병합 정렬	항상 O(n log n)

따라서 무작위 데이터를 메모리 제약 하에 빠르게 정렬할 때는 퀵 정렬(특히 Median-of-Three)이 유리하고, 입력과 상관없이 일정한 성능과 안정성이 필요할 때는 병합 정렬이 유리하다.
